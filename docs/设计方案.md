## 0. TL;DR（先看这 8 条）

1. **架构走"纯数据模型 + 视图轮询"**，不搞 ECS、不搞 TileMap、不搞 3D 物理。模型（站点/线路/列车/乘客）是 `RefCounted` 纯数据；`Node2D` 视图每帧读模型做插值。这样**可以在 headless 模式跑单测和整局加速模拟**，这是本项目最值钱的一条工程约束。
2. **最大风险不是图形，是"画线手感"**。第 1 周必须先做白盒手势原型（灰底 + 圆点 + 拖拽连线），手感不过关立刻换备选交互，别等到美术做完才发现。
3. **乘客是数据不是节点**。原作车厢内不显示乘客，只显示站内等待者（每站 ≤ 6~12 个），所以哪怕模拟 3000 个乘客，渲染量也是常数级，性能天然可控。
4. **寻路用"站点-线路"二部状态图 + Dijkstra**（换乘代价 > 乘车代价），网络一变就重算，几十个节点的规模是微秒级。
5. **列车位置用弧长（arc-length）驱动**，不用 `PathFollow2D`——线路会被玩家随时改写，`PathFollow2D` 的进度语义在路径重建时会跳变，弧长重映射才可控。
6. **固定步长模拟（1/60 s）+ 种子 RNG**，为的是"每日挑战可复现"和"整局无渲染回放测试"。
7. **画面 99% 程序化绘制**（`_draw` 画形状、`Line2D` 画线路、shader 出纸纹），素材需求极低，一个人也能做出完成度。
8. **工期**：单人熟练 4~6 周（每天 4~6h）到可发布；第 1 周末应能玩到"车站 + 画线 + 列车 + 乘客送达 + 溢出失败"的最小闭环。

## 1. 原作机制拆解

### 1.1 三层循环

```
秒级：看站点积压 → 判断要不要调车/改线
分钟级：看周进度条 → 攒资源 → 抽升级卡 → 重新规划网络
一局：拓扑规划（哪条线连哪几站） + 资源取舍（线/车/车厢/桥） + 压力管理（谁会溢出）
```

### 1.2 机制清单（实现视角）

| 维度 | 原作规则 | 实现要点 |
|---|---|---|
| 站点 | 随机出现，形状区分目的地（圆/三角/方，少量菱形/星形等特殊站） | 数据驱动，形状=枚举；`_draw` 绘制，无贴图 |
| 容量 | 普通站约 6 人，换乘站 12 人 | 容量是可升级属性 |
| 溢出 | 站内等待 > 容量 → 外圈计时环，超时即游戏结束 | 计时环用 `draw_arc`，剩余时间可见 |
| 乘客 | 以"目的地形状"表示，随站点出现而生成 | 只存 `{目标形状, 生存期}`；视觉仅站内等待者 |
| 线路 | 拖拽画线连接站点；可拖动站点重排；线路数受限 | 编辑状态机是核心难点（见 §4.3） |
| 列车 | 沿线往返，到站停靠，容量 6（+车厢） | 弧长驱动 + 状态机；端点掉头 |
| 换乘 | 乘客可在中间站换线 | 二部图最短路，换乘有代价 |
| 资源 | 线路 / 列车 / 车厢 / 桥隧 / 换乘站 | 只能用 `Line`/`Train`/`Carriage` 三类主要资源 + 跨河资源 |
| 周期 | 每周结算，二选一升级 | 权重池 + 前置过滤 + 卡片 UI |
| 计分 | 送达乘客数（累计） | 计数器 + 送达反馈 |
| 模式 | 经典城市 / 无尽 / 极限 / 创意 / 每日挑战 | 模式=规则参数集（`ModeConfig`） |
| 地图 | 手绘城市轮廓与河流，地标 | `LevelData` 资源 + 多边形 |
| 氛围 | 极简矢量风 + 生成式氛围音乐 | 纸纹 shader + 分层 loop 音乐 |

### 1.3 三条设计红线（决定"像不像"）

- **信息透明**：玩家永远能看清"谁在等、要去哪、哪站快到点"。所有失败都必须可归因于玩家决策。
- **操作即时**：画线、改线、抽卡都要在 200ms 内给出视觉/听觉回应。
- **惩罚公平**：溢出倒计时给足反应时间（≥ 25s），且可被任何合理操作解除。

### 1.4 范围界定

| 版本 | 内容 |
|---|---|
| **MVP**（第 1 周） | 单张矩形地图、3 种站点形状、3 条线、列车往返、乘客送达计分、溢出失败、暂停/倍速 |
| **V1**（发布线） | 跨河桥隧、特殊形状站、换乘站升级、车厢、环线（可选）、周奖励、无尽/每日挑战、音乐音效、设置/存档/中英双语 |
| **不做** | 多人、3D、自由寻路/AI 对手、Mod、云存档、复杂列车物理 |

> 注：原作线路是**开放折线**（没有环线）。环线、线路删除返还资源属于"对玩家更宽容的差异化设计"，建议做成可选项而不是默认。

## 2. 技术选型

### 2.1 选型表

| 项 | 选择 | 理由 |
|---|---|---|
| 引擎 | Godot 4.7.2 | 已安装、导出模板就位、2D 矢量绘制与 UI 生态成熟 |

| 测试 | GdUnit4（addon） | headless 跑模型单测、热路径压测 |
| 规范 | GDToolkit（`gdformat` / `gdlint`） | CI 里统一格式，避免多人/多 agent 风格漂移 |
| 版本控制 | Git + 现有 `.gitignore`（已忽略 `.godot/`） | 二进制资源用 Git LFS 可选 |

### 3.4 固定步长 + 确定性

```gdscript
# sim/simulation.gd
const STEP := 1.0 / 60.0
var _accum := 0.0

func _process(delta: float) -> void:
    _accum += minf(delta, 0.25)        # 防"死亡螺旋"
    var steps := 0
    while _accum >= STEP and steps < 8:
        tick(STEP)
        _accum -= STEP
        steps += 1
```

- 所有随机数来自 `run_rng: RandomNumberGenerator`（用日期/种子初始化），**禁止**裸 `randf()`。
- 倍速 = 每帧多跑几个 tick，而不是把 `delta` 调大（保证行为一致）。
- 确定性的边界：同机同构建可复现；跨平台浮点不保证逐位一致——所以每日挑战榜只在本地，别做服务器端一致性校验。

## 4. 核心系统设计

### 4.1 地图与水域

- **地图数据**：`LevelData` 里存陆地多边形 + 河道多边形（直接存"带宽度"的河道多边形，不在运行时做折线偏移，简单且可控）。
- **绘制**：背景铺"水色"，陆地用 `Polygon2D` 铺"纸色"，河道用 `Polygon2D` 铺水色；再叠一层纸纹 shader。
- **跨河判定**：线段 ∈ 河道多边形即需要桥/隧道：

```gdscript
func needs_bridge(a: Vector2, b: Vector2, river_poly: PackedVector2Array) -> bool:
    var seg := PackedVector2Array([a, b])
    # 返回被多边形裁剪后"落在多边形内"的片段；非空即相交
    return not Geometry2D.intersect_polyline_with_polygon(seg, river_poly).is_empty()
```

  > 若该 API 行为在特定版本上不符合预期，退化实现：逐条多边形边做 `Geometry2D.segment_intersects_segment`，再用 `is_point_in_polygon` 兜底端点在内的情况。二者都只依赖长稳 API。
- **站点放置**：拒绝采样——在陆地内、距地图边缘 ≥ 120px、距其他站 ≥ 90px、距河道 ≥ 40px（避免贴着河画不出线）。失败重试 40 次，仍失败就放弃本次生成。
- **相机**：世界 2400×1200；开局 zoom 2.0（近看城镇中央），随城镇发展平滑到 1.0（地图铺满窗口）；窗口 2400×1200、`canvas_items` 拉伸。

### 4.2 站点

| 项 | 设计值（起始值，后续按手感调） |
|---|---|
| 图标半径 | 26 px @1080p |
| 默认容量 | 6 人（换乘站升级后 12） |
| 溢出宽限 | 30 s（原作体感 20~40s 区间） |
| 等待者图标 | 16 px，围绕站点呈弧线排布 |
| 出现动画 | 0.25 s scale 0→1 + 一声清亮提示音 |

- **绘制**：`draw_circle` / `draw_colored_polygon`，形状在 `art/shapes.gd` 里用顶点表定义（三角、方、菱形、星、十字）。描边用 `draw_polyline`（`antialiased=true`）或交给 MSAA。
- **等待者布局**（原作是围绕站点的一圈小图标）：极坐标数组 + 每圈容量 N 个，超出容量后自动换圈；实现时预计算 `slot_positions: Array[Vector2]`，乘客只占槽位，避免每帧重排。
- **溢出计时**：`waiting.size() > capacity` 时 `overload_timer += dt`；到 30s → `EventBus.game_over.emit("overload")`。视觉：站点外圈红色进度环（`draw_arc`）+ 图标呼吸抖动；解除后环以 0.3s 淡出。
- **点击/悬停**：仅用于显示"本站等待谁"，不参与画线判定（判定统一由 `LineEditor` 做距离检测，避免多套拾取逻辑打架）。

### 4.3 线路与画线手感（全项目最高风险项）

**数据结构**

```gdscript
class_name LineGeometry
extends RefCounted
var points: PackedVector2Array         # 圆角化后的采样点
var cumulative: PackedFloat32Array     # 弧长前缀和
var stop_offsets: PackedFloat32Array   # 每个站对应的弧长位置
func total_length() -> float
func sample(distance: float) -> Transform2D   # 位置 + 切线朝向
func nearest_distance(p: Vector2) -> float    # 投影到折线的弧长（用于编辑重映射）
```

**编辑状态机**

```
IDLE ──按下(站点上/线端点)──► DRAFT（飞线跟随鼠标）
DRAFT ──悬停到可连接站点──► 吸附预览（合法=本站色，非法=红色）
DRAFT ──抬起在站点上──► COMMIT：追加站/新建线/成环
DRAFT ──抬起在空白处/Esc──► CANCEL
IDLE ──按住已有线路的站点图钉──► EDIT（沿线路滑动重排）
IDLE ──按住端点往回拖──► 收缩线路
```

关键规则：

1. **飞线**：从按下点跟随鼠标，画一条带弧度的虚线（用 `draw_polyline` + 二次贝塞尔，控制点抬到连线中点上方，制造"橡皮筋"感）。
2. **连续画线**：抬起后"笔"仍吸附在当前站，可继续拖出下一段——原作就是这么连续串站的，体验差异极大。
3. **吸附半径 24 px**，吸附时目标站放大 1.15 并出现高亮环；同时预览整条线的新形状。
4. **合法性校验**（提交前）：线资源充足、跨河时桥/隧道充足、不能连到已在该线相邻位置的站（防自环）、不能超线长上限（可选）。
5. **改线不破坏列车**：线路变更后重建 `LineGeometry`，每列车把旧弧长按最近点重映射到新弧长并 clamp。这是"列车会不会抽搐"的关键。
6. **重排**：拖动线路上的站点图钉沿线路移动，相邻顺序交换（用弧长区间判断"滑过了哪个邻居"），松手重建几何。
7. **撤销**：每次提交前把受影响线路的 stops 拷贝到 `undo_stack`（上限 20），`Ctrl+Z` 回滚；这是给玩家的安全网，也方便测试。
8. **视觉**：`Line2D`，`width=10`、`joint_mode=ROUND`、`begin/end_cap_mode=ROUND`、`round_precision=12`。悬停/拖动时宽 12 并轻微发光（第二个 `Line2D` 叠加半透明色，别用真实发光，2D 开销更可控）。
9. **颜色**：8 色预置调色板；新建线路优先选用当前未被占用的颜色，避免删线后重色；可选"点击线路换色"（原作可换色，增强可读性）。
10. **轻点翻转弯曲方向**：线段命中用弧长投影 + `stop_offsets` 判断落在哪两站之间；
    翻转状态存在 `MetroLine.bend_flips`（key = 有序站点 id 对），插站/换序/undo 不会串位。
11. **拖线段插入车站**：按住线段中间拖动，落点是站内且不在本线 → 插入到该段两站之间；
    拖拽预览用两段八向虚线示意插入后的走势。
12. **停留移出车站**：画线过程中指针停在"已在本线上的非相邻站"上 0.8s，画红色进度环，满后把该站移出线路；
    与"拖回上一站立即回退"互补（相邻站走回退语义）。

**圆角折线生成**（同时供线路与列车使用）：

> 重要约束：线路是**八向折线**——任意两站之间只能出现水平线、竖直线、45° 斜线。
> 实现方式是 `LineGeometry.bends_between()` 在几何层插入折点：从起点先走 45° 斜段
> （消耗较短的那个轴），再走剩余的水平/竖直段进站；已经是八向的连接不插折点。
> 站点位置仍是唯一输入，玩家改站序/撤销后几何自动重算，不需要额外约束编辑操作。

```gdscript
# 在拐点用二次贝塞尔替代尖角，输出密集采样点
static func round_corners(pts: PackedVector2Array, radius := 12.0, segs := 8) -> PackedVector2Array:
    if pts.size() < 3: return pts
    var out := PackedVector2Array([pts[0]])
    for i in range(1, pts.size() - 1):
        var p := pts[i]
        var d1 := (p - pts[i - 1]).normalized()
        var d2 := (pts[i + 1] - p).normalized()
        var r := minf(radius, minf(pts[i - 1].distance_to(p), p.distance_to(pts[i + 1])) * 0.45)
        var a := p - d1 * r
        var b := p + d2 * r
        for s in range(1, segs + 1):
            var t := float(s) / segs
            out.append((1 - t) * (1 - t) * a + 2 * (1 - t) * t * p + t * t * b)
    out.append(pts[-1])
    return out
```

### 4.4 乘客与换乘寻路

**生成**

- 每 `spawn_interval`（起始 ~2.2s，随时间递减，用 `Curve` 资源调）在随机站点生成 1 个乘客。
- 目标形状按"地图上该形状站点数量"加权（形状存在感平衡，也保证可达）。
- 早期保底：前 20 个乘客的目标优先选"已有线路能到的形状"，否则新手开局就堵死。

**数据结构**：轻量 `RefCounted`（3 个字段），配对象池。数量级实测上限约 2000，但渲染只取站内等待者。

**寻路：二部状态图 + Dijkstra**

节点两类：
- `S(i)`：站在站点 i（站台）
- `L(i, l)`：在站点 i 的线路 l 上（车厢/站台候车层）

边（有向，权重见下）：
- `S(i) → L(i, l)`：上车/换乘，代价 **1 + 微小惩罚**
- `L(i, l) → S(i)`：下车，代价 **0**
- `L(i, l) → L(j, l)`：同一线路相邻站乘车，代价 **0.01**（让"少换乘、少坐站"同时成立）

对每个目标形状 T，从所有 T 形状站点的 `S(t)` 出发跑一次 Dijkstra，得到 `dist[]`；乘客在 `S(i)` 时选 `dist` 最小的邻居 → 知道"上哪条线、往哪个方向"。

```gdscript
# model/routing.gd 伪代码
func rebuild() -> void:
    _node_count = stations.size() * (1 + lines.size())
    for shape in Shape.values():
        var dist := PackedFloat32Array(); dist.resize(_node_count); dist.fill(INF)
        var pq := []                     # 小根堆：Array + sort 或手写二叉堆（节点数少）
        for st in stations:
            if st.shape == shape: _push(pq, _sid(st), 0.0)
        while pq: ...                    # 标准 Dijkstra 松弛
        _dist[shape] = dist
```

**上车/下车规则**

1. 列车停靠：先下（`rider.target_shape == station.shape` → 送达；否则若需要换乘 → 进本站等待队列）。
2. 再上：按等待队列顺序，若乘客的"下一跳线路 == 本列车线路"且方向一致，且未满载 → 上车。
3. 方向一致判定：乘客下一跳站点在本线路的弧长位置上"在本站的前进方向"，而非简单的站序比较（环线/重排后也成立）。
4. 无路可走：乘客原地等待（自然形成拥堵压力），绝不删乘客——这是公平性的核心。

**性能**：`rebuild()` 只在 `network.version` 变化时触发；站点 ≤ 40、线路 ≤ 7 → 节点 ≤ 320，8 个形状各跑一次 Dijkstra，总计亚毫秒。乘客携带 `route_version`，不一致时惰性重算下一跳。

### 4.5 列车

| 项 | 设计值 |
|---|---|
| 速度 | 150 px/s（在弧长域上推进） |
| 停靠 | 0.6 s（可被"满载"等规则延长） |
| 容量 | 6 + 6 × 车厢数 |
| 端点行为 | 到首/末站掉头（`dir *= -1`） |
| 多车 | 加车时插在最长间隔处；允许视觉重叠（原作也重叠，不做排队） |
| 视觉 | 圆角矩形 28×16，车头小三角高亮，满载时描边变亮 |

状态机：`MOVING → ARRIVING(减速) → DWELL(上下车) → DEPART`。

```gdscript
func tick(dt: float) -> void:
    match state:
        State.MOVING:
            dist = move_toward(dist, target_dist, speed * dt)
            if is_equal_approx(dist, target_dist):
                state = State.DWELL
                dwell_left = DWELL_TIME
                _exchange_passengers()
```

> 为什么不用 `PathFollow2D`：路径重建会重算 progress 语义，且多车/掉头/停靠都需要在弧长域做精确控制。自己维护 `dist` 反而更简单（`sample(dist)` 返回位置 + 朝向）。

## 5. 关键实现片段

### 5.1 列车位置采样（弧长域）

```gdscript
func sample(distance: float) -> Transform2D:
    var d := clampf(distance, 0.0, cumulative[-1])
    var i := cumulative.bsearch(d) - 1
    i = clampi(i, 0, points.size() - 2)
    var seg := cumulative[i + 1] - cumulative[i]
    var t := 0.0 if seg <= 0.0 else (d - cumulative[i]) / seg
    var pos := points[i].lerp(points[i + 1], t)
    var dir := (points[i + 1] - points[i]).normalized()
    return Transform2D(dir.angle(), pos)
```

### 5.3 站点/乘客生成权重

```gdscript
func pick_station(rng: RandomNumberGenerator) -> Station:
    var total := 0
    for st in network.stations:
        total += 1 + st.lines.size() * 2      # 有线路的站更容易来乘客，制造局部压力
    var r := rng.randi_range(0, total - 1)
    for st in network.stations:
        r -= 1 + st.lines.size() * 2
        if r < 0: return st
    return network.stations[0]
```

### 5.4 画线提交的合法性校验

```gdscript
func can_connect(line: MetroLine, from: Station, to: Station) -> StringName:
    if from == to: return &"self_link"
    if to in line.stops and not _is_endpoint(line, to): return &"already_on_line"
    if _needs_new_line and Game.resources.lines <= 0: return &"no_line"
    if _needs_bridge(from.pos, to.pos) and Game.resources.bridges <= 0: return &"no_bridge"
    return &""     # 空 = 合法
```

| 画线手感做不对 | **高** | 直接决定成败 | M1 白盒先行；备选方案：点击两站建线（更易实现，手感差但保底）；请 3 个非开发朋友盲测 |

| 换乘寻路错（坐错车/不下车） | 高 | 玩法失效 | 模型层单测：固定小网络断言"下一步线路/站点"；整局回放截图核对 |
| 视觉"极简但廉价" | 中 | 卖相差 | 先定 token（线宽/圆角/动效时长/配色），再逐元素套用；参考原作截图做对比 |
| 性能（大量乘客） | 低 | 掉帧 | 乘客数据化 + 只渲染等待者；整局无渲染压测脚本 |
| Web 导出限制 | 中 | 少一个渠道 | 用 Compatibility 渲染器、控制内存（音乐 stems 压缩为 ogg）、实测 itch.io |
| 版权/商标风险 | **高** | 法律+下架 | 换名（如 Tiny Transit）、自绘图标、自创作曲、不用原作关卡布局；宣传文案写"灵感来源" |
| 4.7 生态/插件兼容 | 低 | 工具链小坑 | 只用引擎内置 API + GdUnit4；锁定 4.7.2，团队版本一致 |

## 9. 版权与产品化

- **机制不受版权保护**，可以借鉴（线路画法、乘客形状、资源升级、溢出失败）。
- **不要复用**：Mini Metro 商标与名称、原作图标/字体/关卡/音乐。原作图标是版权素材。
- 建议：原创名称 + 自绘图形（形状本身无版权）+ 自制/授权音乐；美术风格可以"极简纸感"但不逐像素临摹。
- 若公开分发，商店页避免使用"Mini Metro"作为标题，可在描述中写"受经典极简地铁游戏启发"。
